# Authentication

Pola ships composable auth primitives under `auth/`. You verify a credential,
load the current user, and expose it to your handlers — or let the framework wire
JWT-cookie sessions declaratively from `Polafile.hcl`.

| Package | Purpose |
|---------|---------|
| `auth/password` | Hash and verify passwords (bcrypt). |
| `auth/jwt` | Sign and verify HS256 JWTs. |
| `auth` | `Authenticator` strategies + `Middleware` for API auth. |
| `auth/authz` | Role/permission checks and a `Policy` builder. |

## Hashing passwords

`auth/password` wraps bcrypt. Hash on signup, verify on login:

```go
import "github.com/polagonow/pola/auth/password"

hash, err := password.Hash("s3cr3t")          // store hash on the user record
ok, err := password.Verify("s3cr3t", hash)    // true when it matches
```

`password.HashWithCost(pw, cost)` overrides the bcrypt cost factor.

## Signing tokens

`auth/jwt` signs and verifies HS256 tokens. `Sign` **refuses to issue weak
tokens** — it errors when the secret is shorter than 32 bytes or the expiry is
not strictly positive, so Pola never mints a non-expiring or weakly-signed token.

```go
import authjwt "github.com/polagonow/pola/auth/jwt"

token, err := authjwt.Sign(map[string]any{"sub": user.ID}, secret, 24*time.Hour)
claims, err := authjwt.Verify(token, secret)   // map[string]any, or error
```

For a login handler, `auth.IssueToken` is a convenience over `Sign` that sets the
`sub` claim and merges any extra claims:

```go
token, err := auth.IssueToken(user.Email, secret, 24*time.Hour, map[string]any{
    "role": user.Role,
})
```

## Protecting API routes

The `auth` package authenticates *API* requests: an `Authenticator` extracts and
validates a credential and returns the user; `auth.Middleware` runs it and injects
the user into the request context; `auth.UserFromContext` reads it back.

Provide a `UserService[T]` that loads a user by username (email, subject claim, …):

```go
// T is your user model; FindByUsername is the only method auth needs.
type UserService[T any] interface {
    FindByUsername(ctx context.Context, username string) (*T, error)
}
```

Wire the built-in `JWTAuthenticator` (validates `Authorization: Bearer <jwt>`)
into the middleware chain:

```go
func Plugin() core.Plugin {
    return core.PluginFunc{
        PluginName: "api-auth",
        Fn: func(r *core.Registry) {
            users := core.MustInvoke[repositories.UserRepository](r)
            authn := &auth.JWTAuthenticator[models.User]{
                Users:  users,          // implements UserService[models.User]
                Secret: []byte(os.Getenv("AUTH_SECRET")),
            }
            r.AddMiddleware(auth.Middleware(authn))
        },
    }
}
```

Read the authenticated user in a handler — it's `nil, false` when unauthenticated:

```go
func (c *Controller) Me(ctx core.Context) error {
    u, ok := auth.UserFromContext[models.User](ctx.Ctx())
    if !ok {
        return ctx.NoContent(http.StatusUnauthorized)
    }
    return ctx.JSON(http.StatusOK, u)
}
```

By default `auth.Middleware` writes `401 {"error":"unauthorized"}` on failure.
`auth.WithOptional()` lets unauthenticated requests through (no user in context);
`auth.WithUnauthorized(fn)` customizes the rejection. `BasicAuthenticator[T]`
handles HTTP Basic instead of Bearer.

### A complete login handler

```go
func Login(c core.Context) error {
    var in struct {
        Email    string `json:"email"    validate:"required,email"`
        Password string `json:"password" validate:"required"`
    }
    if err := c.Bind(&in); err != nil {
        return err // 400/422 already written
    }
    user, err := users.FindByUsername(c.Ctx(), in.Email)
    if err != nil {
        return c.JSON(http.StatusUnauthorized, core.M{"error": "invalid credentials"})
    }
    if ok, _ := password.Verify(in.Password, user.PasswordHash); !ok {
        return c.JSON(http.StatusUnauthorized, core.M{"error": "invalid credentials"})
    }
    token, err := auth.IssueToken(user.Email, secret, 24*time.Hour, nil)
    if err != nil {
        return c.JSON(http.StatusInternalServerError, core.M{"error": "token error"})
    }
    return c.JSON(http.StatusOK, core.M{"token": token})
}
```

> [!NOTE]
> Return the same opaque `invalid credentials` for both "no such user" and "wrong
> password" so an attacker can't tell them apart — the `auth` package's
> `ErrNoCredentials`/`ErrInvalidCredentials` sentinels exist for the same reason.

## JWT-cookie sessions (declarative)

For a browser app, skip the wiring: configure JWT-cookie sessions in
`Polafile.hcl` and Pola registers the `middleware/jwt` middleware (HS256, keyed
off the named env var), storing the token in a cookie.

```hcl
jwt {
  cookie     = "session"
  expiry     = "24h"
  secret_env = "AUTH_SECRET"   # signing key read from this env var
}
```

> [!WARNING]
> `AUTH_SECRET` must be set (≥ 32 bytes) wherever the app runs, including
> production. A missing or short secret makes token signing fail.

To gate whole sections of a **page** app (redirect anonymous visitors to a sign-in
screen rather than answering 401), use `middleware/requireauth` — that's the page
counterpart to the API-oriented `auth.Middleware`.

## Authorization (roles & permissions)

`auth/authz` checks roles on any subject that exposes them (a `Roles []string`
field or a `Roles()` method):

```go
import "github.com/polagonow/pola/auth/authz"

if !authz.HasRole(user, "admin") {
    return c.NoContent(http.StatusForbidden)
}
authz.HasAny(user, "editor", "admin")   // any of
authz.HasAll(user, "billing", "admin")  // all of
```

For permission-based checks, build a `Policy` mapping roles to permissions:

```go
policy := authz.NewPolicy().
    Grant("admin", "posts.write", "posts.delete").
    Grant("editor", "posts.write")

if err := policy.Require(user, "posts.delete"); err != nil {
    return c.NoContent(http.StatusForbidden)
}
```

> The `examples/saas-starter` app demonstrates JWT sessions, CSRF exemptions, and
