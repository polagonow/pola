# DTOs

A DTO is a presentation-layer struct that defines exactly what crosses your
app's HTTP/RSC boundary — kept separate from the ORM models in your data layer.
Convert a model to a response DTO to strip columns it shouldn't expose; map a
request DTO onto a model to persist only the fields a client actually sent.

The `dto` package is small and dependency-free (reflection + `encoding/json`).
It gives you three tools plus a `pola generate dto` scaffold; there is no
runtime configuration.

## The three tools

| Tool | Signature | Direction |
|---|---|---|
| `Convert` / `MustConvert` | `Convert[T](src any) (T, error)` | any → DTO (drops undeclared fields) |
| `Copy` | `Copy[M, D](dst *M, src D) *M` | DTO → model (writes present fields) |
| `Optional[T]` | `struct{ Val T; Present bool }` | tracks absent vs. zero |

`Convert` round-trips through JSON, so a response DTO keeps only the fields it
declares and unexpected client input is dropped rather than bound. `Copy` writes
a DTO onto a model: `Optional` fields only when present, plain fields only when
non-zero, and it skips any destination field tagged `dto:"-"` or
`dto:"readonly"` — shielding columns like `ID` or `Role` from mass-assignment.

## `Optional[T]` for PATCH

A plain `Price float64` can't tell "client sent `price: 0`" from "client omitted
price" — both arrive as the zero value. `Optional[T]` records presence without
pointers so partial updates touch only supplied fields:

```go
type UpdateProduct struct {
    Name  dto.Optional[string]  `json:"name,omitzero"`
    Price dto.Optional[float64] `json:"price,omitzero"`
}
```

> [!NOTE]
> Pair `Optional` fields with the `,omitzero` JSON tag (Go 1.24+) so absent
> fields drop from responses instead of serializing as `null`. `Optional` also
> implements `driver.Valuer`/`sql.Scanner`, so it round-trips through DB columns.

## Generate

```bash
pola generate dto Product name:string price:float description:text
```

Field syntax matches the model generator. This writes `dto/product.go` with
three DTOs — a response, a create, and a partial-update:

```go
// Code generated by pola generate dto; DO NOT EDIT.
package dto

import poladto "github.com/polagonow/pola/dto"

type Product struct {
    ID          int64   `json:"id"`
    Name        string  `json:"name"`
    Price       float64 `json:"price"`
    Description string  `json:"description"`
}

type CreateProduct struct {
    Name        string  `json:"name" validate:"required"`
    Price       float64 `json:"price" validate:"required"`
    Description string  `json:"description"`
}

type UpdateProduct struct {
    Name        poladto.Optional[string]  `json:"name,omitzero"`
    Price       poladto.Optional[float64] `json:"price,omitzero"`
    Description poladto.Optional[string]  `json:"description,omitzero"`
}
```

Required fields get a `validate:"required"` tag on the create DTO; hidden model
fields (e.g. a password hash) stay out of the response but remain valid inputs.

## Use with routes and validation

Bind the request into a DTO, validate it, then map it onto the model:

```go
func (rt *Route) PATCH(c core.Context) error {
    var in dto.UpdateProduct
    if err := c.Bind(&in); err != nil { // decodes body; writes 400 on failure
        return err
    }
    if err := validate.Validate(in); err != nil {
        return c.JSON(http.StatusUnprocessableEntity, core.M{"error": err.Error()})
    }

    product, err := rt.repo.Get(c.Ctx(), c.Param("id")) // fetch first
    if err != nil {
        return c.JSON(http.StatusNotFound, core.M{"error": err.Error()})
    }
    dto.Copy(product, in)                        // apply only present fields
    if err := rt.repo.Update(c.Ctx(), product); err != nil {
        return c.JSON(http.StatusInternalServerError, core.M{"error": err.Error()})
    }
    return c.JSON(http.StatusOK, dto.MustConvert[dto.Product](product))
}
```

> [!TIP]
> Fetch the model before `Copy` (read-modify-write) rather than building a fresh
> one from a partial DTO — that preserves untouched columns and avoids temporal
> inconsistency.
