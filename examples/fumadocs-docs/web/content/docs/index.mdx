# Introduction

**Pola** is a full-stack web framework for **Go** that renders **React Server
Components** inside an embedded JavaScript engine — so you ship one static Go
binary and never run Node.js in production. You write React (`.tsx`) for the UI
and Go for everything else, and the two talk through a typed bridge with no REST
layer in between.

> [!NOTE]
> This documentation site is itself built with Pola. The pages you're reading are
> Markdown compiled to React by a Go-native pipeline (no `fumadocs-mdx`), rendered
> through the real `fumadocs-ui` — with **zero Node.js** at build or runtime.

## Why Pola

- **One binary.** `pola build` embeds your JS/CSS assets (and optionally your
  database migrations) into a single Go executable. No `node_modules` at runtime.
- **React Server Components, in Go.** Server components run in a pooled JS engine
  (Goja by default; V8/QuickJS optional) and stream over the RSC Flight protocol.
- **No API layer.** Call Go functions directly from server components through the
  `@pola/actions` bridge — fully typed, no fetch/handlers to write.
- **Batteries included.** File-based routing, an ORM-neutral data layer, Atlas
  migrations, auth, middleware, mailers, storage, and an MCP server — all
  generated by the CLI.
- **Pluggable everything.** Swap the JS engine, bundler, router, HTTP framework,
  CSS processor, ORM, cache, and storage backend from one config file.

## A taste

A server component that calls Go directly during render:

```tsx
// web/app/page.tsx  (React Server Component)
import { Blog } from "@pola/actions";

export default async function HomePage() {
  const posts = await Blog.listPosts();   // runs Go, no API call
  return (
    <ul>
      {posts.map((p) => (
        <li key={p.id}>{p.title}</li>
      ))}
    </ul>
  );
}
```

```go
// actions/blog_action.go
package actions

type Blog struct{ posts repositories.PostRepository }

func (b *Blog) ListPosts() ([]models.Post, error) {
    return b.posts.All(context.Background())
}
```
