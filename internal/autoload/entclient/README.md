# entclient

Autoloader that generates a Pola plugin providing `*ent.Client` in the DI
container, constructed from the framework-provided `*entsql.Driver`. Runs at
priority 350, after the repos autoload has settled the ORM identity and the
ent client directory.

## Why only ent has an autoloader

Every ORM Pola integrates with follows the pattern *framework plugin registers
the handle → user code resolves it with `core.MustInvoke[T](r)`*. Two of the
three integrations can stop there:

| ORM   | What the framework plugin provides                          | What user code consumes |
|-------|-------------------------------------------------------------|-------------------------|
| gorm  | `*gorm.DB` (`database/gorm/plugin.go`)                      | `*gorm.DB`              |
| beego | `orm.Ormer` (`database/beego/plugin.go`)                    | `orm.Ormer`             |
| ent   | `*entsql.Driver` (`database/ent/plugin.go`)                 | `*ent.Client`           |

Gorm and beego users write `core.MustInvoke[*gorm.DB](r)` / `core.MustInvoke[orm.Ormer](r)`
directly against the framework-provided type. There's no derived type to build,
so no per-ORM autoloader is needed — the analogous plugin already lives in the
framework.

Ent is the odd one out because `*ent.Client` is *generated by the `ent` CLI
from the user's schema files*. Its concrete type name lives at a user-specific
import path (typically `myapp/db/client/ent`) that the framework cannot import.
So instead of the framework registering `*ent.Client` directly, this autoload
emits code **inside the user's project** — under `<repositoriesDir>/ent/pola_ent_client_plugin.go`
— that pulls `*entsql.Driver` from DI and constructs the ent client via
`ent.NewClient(ent.Driver(drv))`. The generated file references the user's
ent client package via `ModulePath + "/" + EntClientDir` (see `polafile.DatabaseEntClientDir`).

Only ent needs this bridge; that's why only ent has a codegen autoloader.

## When it emits

Emits `pola_ent_client_plugin.go` into `<projectDir>/<RepoDir>/ent/` (same
package as the repository plugins) when all of the following hold:

- Discovery.RepoDisco is populated by the repos autoload;
- `RepoDisco.ORM == "ent"`;
- at least one ent repository constructor was discovered;
- `ModulePath` and `EntClientDir` are non-empty.

Populates `Discovery.EntClientDisco` so the pluginimports autoload references
`EntClientPlugin()` in the top-level `PolaPlugins` slice. Since the emitted
file shares the ent repositories' package, pluginimports reuses the same
`repo{PkgName}` import alias — no new imports needed.

## Downstream

Once `EntClientPlugin` is registered, any user constructor can resolve the
client with the standard pattern:

```go
func NewTodoRepository(r *core.Registry) repositories.TodoRepository {
    return &todoRepository{client: core.MustInvoke[*ent.Client](r)}
}
```

No manual wiring, no per-repository ent-driver dance.
