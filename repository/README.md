# Repository

Framework-owned, generic persistence layer — the data-side twin of
`webframework`: one neutral contract, pluggable ORM engines (gorm, beego, ent)
underneath.

```go
// The contract every generated repository interface embeds.
type Repository[T any, ID comparable] interface {
    Create(ctx context.Context, entity *T) error
    Get(ctx context.Context, id ID) (*T, error)
    List(ctx context.Context, params ListParams) (*ListResult[*T], error)
    Update(ctx context.Context, entity *T) error
    Delete(ctx context.Context, id ID) error
}
```

## Why

`pola generate repository` used to emit ~73–128 lines of ORM code per entity
that was ~95% identical between entities. Now the CRUD logic lives here once,
and generated code shrinks to an entity struct, a named interface, and a
~25-line implementation that embeds the generic:

```go
// repositories/user_repository.go (generated)
type UserRepository interface {
    repository.Repository[User, uint] // add custom query methods here
}

// repositories/gorm/user_repository.go (generated)
type userRepository struct {
    repository.Repository[repositories.User, uint]
    db *gorm.DB // extension point for custom queries
}

func NewUserRepository(db *gorm.DB) repositories.UserRepository {
    return &userRepository{Repository: gormrepo.New[repositories.User, uint](db), db: db}
}
```

The named interface stays mockable and extensible; custom methods go on the
generated struct using the retained `db`/`ormer` field.

## Engines

| Package | Backend | Notes |
|---|---|---|
| `repository/gorm` | `*gorm.DB` | PK lookups use an explicit `clause.Eq` predicate — fixes the raw-SQL splice the old generated `First(&e, id)` performed for string IDs. |
| `repository/beego` | `orm.Ormer` | Registers the entity with beego's model cache at construction (idempotent); reads/deletes by reflecting the PK onto the entity, using the `*WithCtx` API. |
| `repository/ent` | app's generated `*ent.Client` (passed as `any`) | Binds to the per-entity sub-client by reflection once at construction (fail-fast on mis-wiring) and drives Create/Update through ent's own `ent.Mutation` interface — `SetField(name, value)` is generated by ent and validates field names and types at runtime. Also fixes the old template's parity gap: the auto-generated ID is now copied back into the entity after Create. |

The ent engine is reflection-backed rather than constraint-based because the
framework can never import an app's generated client package, and ent's typed
builders (per-entity types, per-field setters) leave no compile-time generic
surface to program against from outside the app module. Reflection is confined
to construction-time binding plus stable codegen method names
(`Create`/`Query`/`Get`/`UpdateOneID`/`DeleteOneID`/`Mutation`/`Save`/`Exec`);
field writes go through ent's runtime-validated Mutation API, not raw struct
poking.

## Options

```go
// Assign a fresh ID on Create when the entity's ID is the zero value.
gormrepo.New[Session, string](db, repository.WithNewID(uuid.NewString))

// Override the snake_cased entity name used in wrapped errors.
gormrepo.New[User, uint](db, repository.WithEntityName[uint]("member"))
```

Entities must have an exported `ID` field whose type matches the `ID` type
parameter; constructors fail fast (panic) on mis-declared entities.

## Pagination

`ListParams`, `ListResult[T]` and `DefaultPerPage` live here; generated
projects alias them (`type ListParams = repository.ListParams`) so services,
routes and hand-written code share one definition with the framework.

## Conformance

`conformance_test.go` runs one behavior suite against every engine — CRUD
round-trips, pagination math, params normalization, error labels — mirroring
`webframework/conformance_test.go`.

Known residual difference: the wrapped driver error for a missing row is
`gorm.ErrRecordNotFound` vs beego's `orm.ErrNoRows`. A cross-ORM
`repository.ErrNotFound` is a planned follow-up.
